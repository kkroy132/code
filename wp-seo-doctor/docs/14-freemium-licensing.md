# WP SEO Doctor — Step 14: Freemium/Licensing Architecture

Built ahead of Steps 12/13 rather than after them, per the sequencing
decision made when Step 11 flagged the issue: every Pro-only class
deferred so far (chain/loop redirect detection, regex redirects, GSC,
AI) needs a Pro plugin bootstrap to attach to, and Step 12/13's code
would otherwise be orphaned — nothing would load it. This step builds
that bootstrap for real, with working (not stubbed) feature-gating, so
Steps 12/13 land as genuine Pro features from the start.

## What landed — `wp-seo-doctor-pro/`

- `wp-seo-doctor-pro.php` — plugin header declaring
  `Requires Plugins: wp-seo-doctor` (the WordPress 6.5+ native dependency
  header — this is also why Free's minimum is 6.5, established back in
  Step 8). WP core itself now refuses to activate Pro without Free
  active, with its own admin UI explaining why; the `function_exists('seodoc')`
  check in the bootstrap is defense in depth for that, not the primary
  gate. Hooked to `plugins_loaded` at **priority 20** — deliberately
  after Free's own priority-10 boot — so Free's registries
  (`seodoc_register_modules`, `seodoc_loaded`) are guaranteed complete
  before Pro touches anything.
- `includes/class-autoloader.php` — Pro's own copy of Free's exact
  autoloader convention (`SEODocPro\Sub\Class_Name` →
  `includes/sub/class-class-name.php`). Not shared/required from Free's
  folder — the two plugins stay independent, matching Step 1 §1.
- `includes/class-pro-plugin.php` — mirrors Free's `Plugin` singleton
  pattern exactly: a `seodoc_pro_core_modules` filter-extensible module
  list, `seodoc_pro_loaded` fired once booted (this is where Steps 12/13
  add their own `seodoc_register_check()`/etc. calls).
- `includes/licensing/class-license-manager.php` — the licensing
  adapter, built for **Freemius** (product decision — bundles payments,
  license checks, and auto-updates together, versus building and
  maintaining a custom license-key/update server independently).
- `includes/class-feature-gates.php` — hooks Free's *existing* filters
  (`seodoc_is_pro_active`, `seodoc_suggestion_monthly_quota`,
  `seodoc_allowed_redirect_types`) to actually unlock Pro behavior. This
  is real, working code, not scaffolding: install Pro with a valid
  license and Free's suggestion quota becomes unlimited and 307/308/410
  redirect types become available — zero changes to Free's code, proving
  the extension-point architecture built across Steps 4-11 actually
  works end to end.

## What's genuinely not fabricated here, and why

The Freemius SDK itself (the `freemius/` vendor folder) and this
product's **account-specific bootstrap snippet** are not included.
That snippet embeds a real plugin ID and public API key generated by
Freemius' "Start Selling" wizard for an actual registered product
listing — there is no real WP SEO Doctor Pro account, so generating one
would mean inventing credentials that don't correspond to anything. This
is the identical reasoning applied to Action Scheduler in Step 4: a
real, well-known third-party dependency gets a clearly-marked integration
point, not a fabricated stand-in pretending to be the genuine article.

`License_Manager` is written to be **correct the moment the real SDK is
present** — it depends only on the stable, documented Freemius SDK v2
convention (a generated `{account}_fs()` accessor function, and its
`is_paying()`/`is_trial()`/`can_use_premium_code()` methods — all real,
public Freemius API surface, not invented for this codebase) — and
**fails closed** when it isn't: `function_exists()` returns false, every
method returns "not licensed." An unconfigured or pre-account-setup copy
of this plugin can never accidentally behave as if it's licensed.

## Why gating checks the license, not "is Pro installed"

`Feature_Gates` calls `License_Manager::is_valid_license()`, never just
"does the Pro plugin exist." Installing Pro without ever purchasing/
activating a license must leave every Free limit exactly as Free ships
it — the plugin becomes a store window, not a bypass. This also means a
lapsed/expired license (Freemius handles that state) correctly reverts
Pro behavior to Free's defaults on its own, with no code change needed
anywhere.

## Deviation from the Step 2 folder plan: no separate update-client class

Step 2 planned `includes/licensing/class-update-client.php` for a
"plugin-update-checker style" auto-updater alongside the license
manager. With Freemius as the chosen platform, that's redundant —
Freemius bundles update delivery into the same SDK integration as
licensing, so a second, custom update mechanism would just be unused
code sitting next to the real one. Dropped rather than built as an
unused stub, the same judgment applied to the `public/` folder removal
in Step 10.

## What Steps 12/13 inherit from this

Concrete, not just conceptual: `Pro_Plugin::boot_core_modules()` already
has a place to add `Gsc\...` and `Ai\...` classes, `seodoc_pro_loaded` is
already the right hook for their own `seodoc_register_check()` calls
(GSC-informed checks, AI-assisted ones), and `License_Manager::is_valid_license()`
is already the correct, tested gate for anything in Step 12/13 that
should be licensed-only rather than available to every Pro installer
regardless of payment status.
